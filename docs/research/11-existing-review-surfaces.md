Weakness notes (per user hints):

- Copy-list pasting: the only machine-captured decision channel in AloneGodot is clipboard to chat. No file is written, nothing an agent can poll. localStorage is per-browser-origin and per-file path (file:// origin), unreachable by agents.
- Stale pages: presentation.html embeds its catalog (143 entries) and nothing refreshes it when a manifest changes; `gallery-refresh.patch` and `presentation-before.html` / `catalog-before.json` backups in `.mz/task/2026_11_12_fal_run_validation_redraw/` show the refresh is manual and risky (single 100KB line diffs). `review/index.html` is a stale shell vs the source (data 0.8.0, source 0.10.0).
- Re-spawned validation-mode task: the repo shows `.mz/task/2026_11_12_build_art_validation` (plan: one batch, four files each under 300 lines) as the canonical build; I found only 3 validation/presentation task dirs in `.mz/task` (38 total), so I could not confirm "~15 spawns" from disk. The reason it recurs is structural: validation mode lives inside one page's catalog, so every new artefact type or batch needs a fresh edit.
- Identity: `[id, path]` means a regenerated image at a new path is automatically "unreviewed" (good) but old decisions silently vanish with no history.
- Fragmentation: 4+ asset-record schemas; 3 different "review verdict" locations (`review_status` in manifests, `presentation_review.json`, localStorage).
- Offline vs CDN: Three.js demos need jsdelivr; video page promises "asks the network for nothing".
- Pre-existing issue to surface (housekeeping): `art/progression/presentation.html` has no generator; `review/index.html` is a stale copy. Offer a separate pass.

## 2. The review-page contract (V `contracts/review-page/schema.json`, version 0.10.0)

Purpose (schema description): "One section of the review page of a film": `review/data/<section>.js` holding `window.REVIEW_DATA.<section> = <doc>`, read by `review/index.html`. dramakit writes `drama`, falkit `fal`, the Resolve plugin `resolve`; each writes only its own and the page omits missing sections. Times are seconds from film start. Paths relative to `review/`, forward slashes, so it works from disk. Text is shown as text, never markup. Designed around gates (G1-G5, fal-plan, conform, render) where a human approves before spend.

Top level. Required: `contract_version`, `section` (drama|fal|resolve), `written_at`, `needs[]`. Optional: `writer`, `qc[]`, `gate`, `film`, `beats[]`, `song`, `shots[]`, `audio[]`, `assets[]`, `changes`, `observed[]`, `canon[]`, `plan`, `attempts[]`, `pairs[]`, `drift[]`, `timeline`, `render`, `keep_out[]`.

Key definitions (required fields in brackets):

- need [level, text] + rule, shot, where: "what the person at the gate must look at, most serious first".
- gate [id, asks] + message (full text so chat stays 5-10 lines).
- qcRow [shot, code, severity fyi|issue|blocker, disposition open|will_fix|best_possible|creative_intent, source judge|agent|user|check, decided_by user|agent|none] + attempt, note. This is the closest thing to a decision record (blocker only user may clear).
- film [title, package_id, mode, runtime_s] + aspect_ratio, resolution, carried, brief.
- shot [id, order, track V1|V2, start_s, end_s, origin, text, characters, props, refs, findings] + scene_id, beat_id, camera, line, muted, window, sketch (review-only), change new|changed (vs last approved), insert_over, states, location.
- beat [id,start_s,end_s]; cue [id, kind speech|music|sound, label, start_s, end_s]; song [length_s, sections] + bpm.
- asset [id, kind, source, generated, used_by] + subject_id, file, brief.
- changes [against, approved_at, new, changed, removed] = diff vs last approved version.
- observed row [shot, differences, proposal]; proposal [kind start_state|carried_sentence|retake, text, status open|accepted|rejected].
- plan [plan_id, spent_usd] + estimate_usd, file.
- attempt [step, n, kind image|video|speech|music|sound, state reserved..released (10 states), chosen, endpoint] + shot, asset, reason, usd, file, last_frame, verdict, repairs, redraws, judge, metrics, pick, at, prompt. This is a versioned-take model: n-th submission per step, `chosen` marks the one the cut uses.
- judge [decision pass|fix|redraw|flag|relip, why] + failed[], minor[], not_judged; judgeFinding [question, severity critical|major|minor, evidence] + from_s,to_s.
- pick [over, both_orders, applied, why]; pair/pairQuestion (cut-join continuity judgements).
- metrics: faces (similarity, skin), audio_follow, lip_offset, speaker, prefilter(exposure, blur, hash, duplicate_of), method (model versions).
- drift series/point, canonEntry, keepOutEntry, timeline [duration_s, tracks], render [file, qc].

Lifecycle machinery in `review_page_io.py`: `ReviewFolder` (atomic writes via rename), `Gate`, `QcRow`/`with_qc`, `RefreshRecord` (args + file list + stamp of mtimes/hashes), `refresh_films` and `run_refresh_hook` for PostToolUse hooks (`plugins/{dramaturgy,fal-media,davinci-resolve}/hooks/refresh.py`, matcher `^(Write|Edit|MultiEdit|Bash)$`, always exit 0, logs to `review/refresh.log`), `ensure_root_entry` (`<film>/review.html` meta-refresh with a generated mark), `open_page`. Shell is built from `shell.html + review.css + review.js` by `tools/sync_contracts.py` into one inlined `index.html`; consumers.json lists `review-page` (schema users: davinci-resolve, dramaturgy) and `review-page writers` (adds fal-media, which has no validator and is held to the schema by tests). `make js` runs `node --test` on pure functions of review.js.

Fit for a marketplace hub: the transport (`window.X = ...` script files, relative paths, file:// safe), the staleness/refresh hook, atomic writes, and the "writers each own a section" idea are reusable. The schema itself is film-specific (time axis, shots, gates, fal ledger) and should not be extended; use it as a pattern.

## 3. Decision capture today: three patterns, none shared

1. Browser-only + clipboard (A validation mode): approve/redo, localStorage, paste to chat.
1. Chat gate (V): AskUserQuestion Approve/Reject, then CLI stamps `--approved <gate>` (silence is never approval; `Status: blocked`).
1. Triage file (V): `<round>/decisions.json` with waiver/dismiss/fix/resolve + `by: user` + verbatim reason, applied with `dramakit review decide` which refuses invalid input and writes nothing.
   The agent-readable file exists only in (3), and there the user answers in chat, not in the page.

## 4. Recommendation for the generalized review hub

Reuse:

- Section-file transport and relative paths (`review/data/<section>.js`), or better a plain `items.json` served over localhost (a local server removes the file:// limit and gives a POST channel; keep a file:// read-only fallback).
- `ReviewFolder`-style atomic writes + `RefreshRecord` stamping + PostToolUse refresh hook, so pages are never stale (fixes presentation.html).
- QcRow vocabulary: severity (fyi/issue/blocker), disposition, `decided_by`, `source`. Map directly: approve -> `best_possible/accepted`, redo -> `will_fix`.
- Attempt model (step, n, chosen, state, file, endpoint, request_id, usd, judge) as the `versions[]` entry; `pick` for A/B comparison.
- From validation.js: shuffled queue, keyboard Approve/Redo/Back, resume at first undecided, progress counter, `textContent` only, storage-failure fallback.
- From manifests: sha256, dimensions, request_id, model, plan (already in final-slides manifest) as version provenance.
- From package_progression.py: thumbnail-to-WEBP embedding as an optional "offline bundle" mode.

Proposed contract (sketch):

```
hub.json: {contract_version, project, written_at, writer, items[]}
item: {id, kind: image2d|sprite|spritesheet|model3d|audio|ui_screenshot|graph|video|doc,
       group, title, note, tags[], needs_review,
       versions: [{n, file, thumb, sha256, created_at, source:{model,request_id,plan}, usd,
                   meta:{w,h,duration_s,tris,fps,frames,...}, judge?, chosen?}],
       status: pending|approved|redo|blocked   (derived from last decision),
       links: {manifest, brief, prompt}}
decisions.jsonl (append-only, one line per decision, the file agents read):
  {item, version, sha256, decision: approve|redo|hold, note, decided_by: user, at, session}
```

Keep decisions append-only and keyed by (item id, version sha256): fixes the silent-vanish on regenerate, gives history and a "redo reason" field that clipboard lists lack. Agents read the reduction (latest per item) and write `redo` to the plan queue. Never mix agent output into the decisions file; agents write to the hub's items (status `awaiting_review`).

Generator: one script (Python, stdlib+Pillow optional) with per-source adapters that read the existing manifests (progression/\*, pilot|full art_manifest, remaining-queue, asset-audit, ui-concepts) and emit `items[]`; regenerated by a refresh hook, not hand-patched. Server: `python -m http.server`-style plus one small POST endpoint appending to decisions.jsonl; serve from project root so `../` paths resolve.

Missing for specific kinds (not present anywhere today):

- 3D: no model viewer. Three.js exists only for card depth parallax (card-parallax.html, CDN, base64 inline). Need GLB/glTF viewer (orbit, wireframe, material channels, tri count, bounds, scale reference), and a "Godot import" screenshot kind. Pin and vendor three locally (no CDN).
- Audio: no player at all in A or V (video page has audio lane timing only, no waveform playback). Need `<audio>` with waveform/loudness (LUFS, peak, duration, loop point), A/B switch between versions, loop toggle.
- Sprites: need pixel-snapped zoom (image-rendering: pixelated), checkerboard/transparent background toggle, spritesheet frame stepper with fps and per-frame onion skin, atlas/anchor overlay, size vs power-of-two checks. Current `img` uses object-fit contain only.
- Design graphs: the progression graph is bespoke (progression-data.js nodes/requires/any); no generic graph item. Needs `kind: graph` pointing to a data file + a renderer plug-in (Mermaid/d3 or the existing view.js), and per-node decisions (item id = node id) plus the `requires`/`any` edge semantic. Mermaid/dependency choice needs the user's approval (dependency rule).
- UI screenshots: per-viewport variants (1920x1080 ... 1024x768), pixel diff vs previous version, links to `layout-results.json` machine verdicts. verify.mjs outputs can feed `judge`/`meta`.
- Cross-cutting: before/after compare slider between versions, redo note field, batch select, filter by status/group/kind, per-item machine checks (dims, alpha, hash dedupe: reuse `prefilter.duplicate_of` idea), dark/light theme from review.css tokens, a11y live regions (already in validation.js).

Two-perspective note: a perfectionist would want a typed schema + validators + sync tool like contracts/ (JSON Schema, consumers.json); a pragmatist would ship items.json + decisions.jsonl + one adapter per manifest now and add schema when a second consumer appears. Recommendation: pragmatic first (items + append-only decisions + refresh hook + adapters), with the schema written only for `decisions.jsonl` since agents depend on it.
